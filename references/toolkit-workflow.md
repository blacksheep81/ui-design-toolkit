# 五步 UI 设计流程

整合自用户提供的 UI Design Toolkit 与 resources.csv，2026-10-11。资源表保留来源字段，不代表已逐项核实、安装或获得素材许可。各补充资料在对应参考文件中保留来源与核实范围。

## 1. 读懂需求

确定主要任务、受众、页面类型和设计方向。营销页重行动，后台重操作效率，文档重阅读，作品展示重作品本身。已有项目先读取现有 PRODUCT.md、DESIGN.md、组件和 token；用户指定风格与现有设计系统优先。只有理解分歧会实质改变结果时才澄清。

## 2. 找参考

需要先建立设计系统、探索多方案、优化业务界面的视觉克制程度，或使用新增社区教程时，读取 [社区方法与核实范围](community-methods.md)。

按任务读取 [已有设计参考站](design-resources.md) 或检索 [分类资源 CSV](../resources.csv) 的 category、description_zh 与 source_post_url 字段，选少量相关参考，提炼层级、密度、导航、响应式和状态设计。链接及产品功能按使用时的官网核实；资源条目不意味着必须安装对应工具或 skill。

- 整站：Godly、Awwwards、Land-book。
- 产品流程：Mobbin、Refero；注意区分真实流程截图与概念作品。
- 局部组件：Navbar Gallery、CTA Gallery、Footer Design、Supahero、Component Gallery。
- 设计方法：Anthropic frontend-design、Impeccable、Awesome DESIGN.md。使用实际文件前读取其内容并适配当前项目。
- Refero MCP 等连接可在已配置时使用；未配置时采用普通参考读取，不假定服务可用。

## 3. 定设计系统

复用项目组件、设计 token 与已安装依赖。新项目选择符合产品的系统，或制定精简的颜色、字体、间距、控件和响应式约定；需要长期维护时记入 DESIGN.md。布局从真实任务和内容出发，视觉强调集中在有意义的位置，具体断点和尺寸由内容与视口决定。

## 4. 生成代码

用真实内容或明确标注的示例数据。控件标签说明动作，错误信息提供恢复路径，空状态给出下一步。图标保持同一套风格，图片体现实际对象。动效服务状态变化或交互反馈，支持减少动态效果偏好；复杂效果优先复用已有实现。Figma 工作遵循已配置工具的对应技能和项目组件规则。

## 5. 交付前评审

- 检查信息层级、分组、主要操作与任务匹配度，并对照 [20 条 UI 设计原则](principles.md)。
- 检查相关控件的 hover、focus、disabled、loading 以及页面 empty、error、success 状态。
- 检查键盘操作、可见焦点、语义与图片替代文字、实际文本对比度和颜色之外的状态表达。
- 在相关桌面和移动尺寸用真实长文本检查溢出、重叠和触控区域；窄屏标签可合理换行。暗色模式存在时一起检查。
- 检查内容导致的布局跳动与图片加载；性能指标以实际测量为准，不从截图推断。
- 审视模板化设计：无业务理由的紫蓝渐变、重复三栏卡片、卡片套卡片、装饰性毛玻璃、每段同样的入场动画、虚构指标和空洞文案。依据 brief 和可读性判断，保留有明确用途的表达。
- 交付实现时渲染、截图并验证主要交互；交付建议时说明具体元素、改法和理由。报告实际验证范围。
