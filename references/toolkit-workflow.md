# 五步 UI 设计流程

整合自用户提供的 UI Design Toolkit 与 resources.csv，2026-10-11。资源表保留来源字段，不代表已逐项核实、安装或获得素材许可。各补充资料在对应参考文件中保留来源与核实范围。

## 1. 读懂需求

确定主要任务、受众、页面类型和设计方向。营销页重行动，后台重操作效率，文档重阅读，作品展示重作品本身。已有项目先读取现有 PRODUCT.md、DESIGN.md、组件和 token；用户指定风格与现有设计系统优先。需求缺少会实质影响实现的交互决策时，指出缺口，问 1–3 个具体问题并给推荐选项。依赖答案的部分等用户确认，其余按已有约定继续。

落地页、后台、仪表盘或设置页在确定主任务后，读 [页面模式](page-patterns.md)，按页面类型选信息结构和必要状态。

## 2. 找参考

需要先建立设计系统、探索多方案、优化业务界面的视觉克制程度，或使用新增社区教程时，读取 [社区方法与核实范围](community-methods.md)。

按 [设计问题选资源](toolkit-resource-directory.md)，提炼层级、密度、导航、响应式和状态设计。参考品牌时用 [DESIGN.md 工作流](design-md-template.md#借用品牌设计规范)。

## 3. 定设计系统

复用项目组件、设计 token 与已安装依赖。新项目选择符合产品的系统，或制定精简的颜色、字体、间距、控件和响应式约定；需要长期维护时记入 DESIGN.md。布局从真实任务和内容出发，视觉强调集中在有意义的位置，具体断点和尺寸由内容与视口决定。需要 claude.ai 风格或扁平极简界面时，可参照 [Claude 风格扁平设计规范](claude-design-system.md)（平台专属细节可选）。

涉及浅色与暗色主题时读 [暗色模式](dark-mode.md)，中文内容读 [中文排版](chinese-typography.md)，有图表或指标卡时读 [数据可视化](data-visualization.md)。

## 4. 生成代码

用真实内容或明确标注的示例数据。控件标签说明动作，图标保持统一风格。按 [交互状态与动效规则](accessibility-states-motion.md) 实现并验证。Figma 工作遵循已配置工具的流程与项目组件规则。

## 5. 交付前评审

对照 [UI 原则](principles.md)、[反 AI 模板味清单](anti-slop.md) 和 [八维视觉自评](visual-self-review.md) 检查实际页面。渲染、截图并验证主要交互，说明具体验证范围。需要书面结论时按 [UI 评审模板](review-template.md) 记录问题、依据和验证范围。
