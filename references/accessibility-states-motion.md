# 可访问性、状态、动效与响应式

用途：实现与交付评审时的硬性检查项。数值来自 WCAG 2.2 与常见实践，项目规范更严格时以项目为准。

## 可访问性

- 对比度：正文 ≥ 4.5:1，大字（≥ 24px 或 ≥ 18.66px 粗体）≥ 3:1；图标、输入框边框、焦点环等非文本元素 ≥ 3:1。用 WebAIM 对比度检查器或浏览器 DevTools 实测，包括 hover、禁用和暗色模式。
- 焦点：所有可交互元素键盘可达，顺序符合视觉；使用 `:focus-visible` 显示清晰焦点环，不可只 `outline: none`。
- 语义：按钮用 `<button>`，链接用 `<a>`；表单有关联 `<label>`；图标按钮有 `aria-label`；标题层级不跳级。
- 点击目标：不小于 24×24 CSS px（WCAG 2.2 AA），触屏主操作建议 44px 左右。
- 信息不只靠颜色表达；错误信息靠近字段并说明如何修复。

## 状态清单

每个数据驱动的视图都覆盖：

| 状态 | 要点 |
| --- | --- |
| 加载 | 骨架屏贴合最终布局，避免跳动；超过约 1 秒才显示进度；按钮提交时禁用并显示进行中 |
| 空 | 说明为什么为空 + 一个主操作（创建、导入、清除筛选）；首次使用与“筛选无结果”分开写 |
| 错误 | 用人话说明发生了什么、数据是否保存、下一步（重试、联系、返回）；保留用户已输入内容 |
| 部分/离线 | 标明数据的时效，允许局部重试 |
| 成功 | 就地确认变化；可撤销的操作优先提供撤销而非确认弹窗 |
| 极端内容 | 超长文本、长单词/URL、0 条与大量数据、缺图、多语言长度 |

## 动效

- 动效服务于解释变化：出现、展开、确认、位置关系。时长一般 120–300ms，退出比进入短；使用 ease-out 类曲线。
- 只动画 `transform` 与 `opacity`，避免布局抖动。
- 遵守 `@media (prefers-reduced-motion: reduce)`：关闭视差、自动播放与大位移，保留必要的淡入或直接切换。
- 一个页面最多一处主要编排动效；不要让每个区块都有入场动画。

## 响应式与移动端

- 移动优先编写样式；至少检查 375、768、1280px，以及横屏与 200% 缩放。
- 不出现横向滚动；表格在窄屏改为卡片列表或允许容器内横滚并固定首列。
- 标题字号在移动端明显收缩（可用 `clamp()`）；正文不小于 16px，避免 iOS 输入框缩放。
- 底部固定操作栏考虑安全区 `env(safe-area-inset-bottom)`；次要操作在移动端用底部弹层而非居中弹窗。
- 触屏没有 hover：hover 才显示的信息需有点击替代。
