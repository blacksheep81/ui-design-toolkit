# 国际化与多语言界面

用途：界面需要支持多种语言或地区时使用。即使当前只做中文，只要将来可能翻译，布局和文案的写法就应提前留出余地。只面向单一语言且没有翻译计划的项目可以跳过。

## 文本长度

- 同一句话在不同语言中的长度差别很大：中文、日文通常最短，英文较长，德文、俄文、法文更长。短标签（按钮、菜单、表头）翻译后变成原来的 2 倍并不少见，长段落的膨胀比例较小。
- 控件宽度由内容决定：按钮、标签、导航项不写固定宽度，允许换行或设置最小/最大宽度；容器用弹性布局而不是按中文字数量好的像素。
- 用最长的目标语言（没有时用把文字加长一倍的伪翻译）跑一遍主要页面，检查截断、溢出和重叠。
- 截断只用于次要信息，并提供查看全文的方式；按钮和错误信息不截断。
- 行高也要留余量：泰文、越南文、阿拉伯文等带上下附加符号的文字需要更高的行高。

## 文案的写法

- 不拼接句子。`"共 " + n + " 条"` 在其他语言里语序不同；使用带占位符的完整句子，交给翻译调整顺序。
- 处理复数与数量：英文有单复数，俄文、阿拉伯文有更多形式，使用支持复数规则的 i18n 库（ICU MessageFormat 等），不自己写 `n > 1 ? "s" : ""`。
- 文字不做进图片；必须有时为每种语言提供版本，并给出替代文字。
- 避免只在一种文化中成立的比喻、谐音和手势图标；图标含义在目标地区是否一致要确认。
- 给译者上下文：同一个词在按钮和标题中可能要译成不同的词，键名和注释说明使用位置。

## 日期、数字与货币

- 用平台的本地化 API 格式化，不手写格式：Web 上是 `Intl.DateTimeFormat`、`Intl.NumberFormat`、`Intl.RelativeTimeFormat`。
- 日期顺序因地区而异（`2026/3/5`、`3/5/2026`、`5.3.2026`），纯数字日期容易误读；空间允许时写出月份名，数据交换用 ISO 8601。
- 千分位与小数点符号不同（`1,234.5` 与 `1.234,5`）；中文习惯“万”“亿”，英文用 K、M、B。
- 货币写明币种，符号位置和小数位按地区规则；不同币种不直接比较大小。
- 时间写明时区或转换为用户本地时间；一周从周日还是周一开始按地区决定。
- 姓名、地址、电话的表单不要按单一国家的格式写死：不强制“姓 + 名”两个字段的顺序，不假定邮编位数。

## 从右到左（RTL）语言

支持阿拉伯文、希伯来文等时：

- 在根元素设置 `dir="rtl"` 和正确的 `lang`，让浏览器处理文字方向。
- 用逻辑属性代替物理方向：`margin-inline-start`、`padding-inline-end`、`inset-inline-start`、`text-align: start`，这样同一份样式在两种方向下都成立。
- 整体布局镜像：侧栏、导航顺序、进度方向、返回箭头都翻转。
- 不镜像的内容：媒体播放控件、时钟、图表的时间轴、数字、品牌标志、不表示方向的图标（如勾号）。
- 混排的拉丁文、数字和链接容易出现顺序错乱，逐页检查；必要时用 `<bdi>` 或 `dir="auto"` 隔离用户生成内容。

## 字体与语言标记

- 在 `<html>` 上设置 `lang`，局部的其他语言片段单独标注；它影响读屏发音、断行和字形选择。同一个汉字在简体中文、繁体中文、日文中的字形不同，`lang` 标错会显示成别的地区的字形。
- 字体栈为每种目标文字提供回退；品牌字体不覆盖的文字要有风格接近的替代。
- 中文、日文、韩文不使用斜体和全大写；这类依赖拉丁字母特性的样式按语言关闭。中文细则见 chinese-typography.md。

## 语言切换

- 语言选择器用各语言自己的写法列出（“English”“日本語”“العربية”），不用国旗代表语言。
- 默认按浏览器或系统语言选择，允许手动更改并记住；切换语言后停留在当前页面。
- 地区（货币、日期格式）与语言是两个设置，必要时分开。

## 检查

1. 用最长的目标语言或伪翻译检查主要页面的截断与溢出。
2. 搜索代码中的字符串拼接、手写日期与数字格式、固定宽度的文字容器。
3. 检查 `lang`、`dir` 是否正确设置，RTL 下布局与图标方向是否正确。
4. 检查图片中的文字、图标和颜色的文化含义。
5. 报告实际检查过的语言，未检查的语言不声称已支持。
