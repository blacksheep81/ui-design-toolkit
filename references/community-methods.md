# 五篇社区 UI 来源与方法

2026-10-11 在浏览器读取五篇原帖。以下是原创操作归纳，区分已读方法、资源推荐与未能读取的媒体，不复制原帖全文。

## 克制的业务界面：Samgor

来源：[原帖](https://x.com/biggor888/status/2094689987803455494)。已读取完整正文。

用于后台、工具和高频操作页面：

- 以界面用途、信息密度、平台习惯和使用频率决定尺寸与间距，避免把所有产品套进一个规格。
- 设置、开关和辅助工具保持次要层级；用位置、分组、状态反馈与轻量视觉差异区分主次。
- 常用动作采用熟悉的图标语义，优先项目图标库或平台符号。自定义图标保留可识别轮廓与比例，必要时提供文字名称和 tooltip。
- 实屏比较新组件与同屏元素；过大、过重、突兀或降低信息密度时，缩减视觉权重。

这是业务工具的默认取向；有明确品牌和展示需求的页面按任务调整，不把克制解释为所有页面都必须相同。

## 探索真正不同的方向：Oil UI

来源：[鱼皮推荐帖](https://x.com/yupi996/status/2106618315779252596)、[Oil UI 官方 README](https://github.com/oil-oil/oil-ui)、[作品画廊](https://ui.oiloil.org/)。已读取原帖、作者回复和公开 README；未读取 Pro 内容。

用于新产品或用户要求探索风格时：

1. 识别产品品类，研究相关产品如何服务任务，把“高级、简洁”等形容词转成字体、密度、留白、色彩占比等决定。
2. 从产品题材、材质、场景或跨领域视觉语言出发构建方向；操作与阅读页面让内容先出现，营销页面才强调说服性首屏。
3. 需要多方案时，在版式、字体、配色、主视觉多个维度拉开差异，而非只换主题色。并排比较首屏明暗与内容分布；相似时先调整构图。
4. 把预览放在同一对比页，桌面和手机采用相同内容与视口比较，结合用户具体反馈继续精修。已有确定方向或局部修补无需强制做多方案。
5. 将有记忆点的表达放在少数关键时刻，其余界面支持主要任务；根据真实截图检查并删去冗余文字、线条和框。

本文件归纳公开方法，不引入该 skill 的更新脚本或 Pro 功能。帖子中的价格、作品数和更新方式是当时陈述，使用时查当前官方说明。
